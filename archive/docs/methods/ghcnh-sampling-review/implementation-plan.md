# GHCNh implementation plan and quick feasibility assessment

20 October 2026. The numerical criteria are agreed. The independent selection driver is implemented and its 64-cell pilot has passed; see the [measured pilot report](pilot-report.md). Integration with the numbered manuscript pipeline remains pending. This note specifies the design and remaining integration work.

## Feasibility

The computation is practical for a one-off run. Local window searches are inexpensive; network retrieval and downstream recomputation will dominate. The new `scripts/sample_ghcnh.R` driver implements selection and restart checkpoints. The pre-implementation estimates below are retained for comparison; use the pilot report for measured resources.

| Measured check | Result |
|---|---|
| Cached local benchmark | 723,789 matched observations at 60 stations: 50 random stations plus 10 additional coverage failures |
| Read and prepare that subset | 0.90 s; 44.2 MiB for the resulting table |
| Search the default rolling windows | 0.244 s total; median 0.004 s and maximum 0.007 s per station |
| Agreement with previous criterion assessment | All 60 selected endpoints or coverage failures match |
| ERA5 transfer probe | Three primary variables for one location and one 24-hour interval: 3.93 s, including the reader's full chunk transfers |
| NOAA annual transfer probe | One 2025 station file: 572,436 bytes in 0.90 s |
| Full cached station inventory | 37,468 stations with usable coordinates/elevation occupy 3,991 cells at 200 km, before archive availability or pressure screening |
| Existing storage | Annual source files: 16.56 GiB across 31,338 files; GHCNh ERA5 station files: 2.73 GiB across 2,146 stations |
| Available disk space | Approximately 50 GiB at the assessment time |

The local benchmark checks the coverage search, including window-specific outlier removal; it does not include source parsing, formula evaluation, step fitting or a global run. It evaluates all daily endpoints cheaply using cumulative raw-coverage counts, and performs window median/MAD calculations only where raw coverage could pass. Only 47 windows required those calculations in this benchmark. Removing observations cannot make a raw-coverage failure pass, so this shortcut preserves the exact daily search and adds no scientific criterion.

ERA5's current single-levels layout places 2022–2026 in two temporal chunks per spatial block. Reading the three primary variables therefore needs approximately twice the transfers in the small probe when neither temporal chunk is reusable. At the observed latency, 4,000–8,000 entirely uncached candidates with four workers imply roughly 2–4.5 hours for primary ERA5 alone. Five annual NOAA files per candidate add about 1–2.5 hours at the single measured transfer rate. These are arithmetic scenarios, not a full-run forecast: actual annual availability, early pressure-coverage rejection, existing caches, spatial reuse, server load and retries change the cost. Retained-only covariates and ERA5-Land add work. A run lasting several hours or overnight is plausible; a small direct-inventory pilot should establish the final estimate.

There are fewer than 4,000 potential cells in this inventory, but candidates attempted can exceed that count. The 2,563-cell count in the earlier criterion assessment applied only to the narrower cached candidate pool. Neither count predicts the accepted network.

## Execution and caching

1. **Freeze the setup once.** Save the settings, station inventory, annual file catalogues and randomized candidate order before parallel work. Process cells in a fixed order and randomize sorted station IDs once using seed 11. Reuse this order on restart; do not draw new candidates based on which downloads finish first. Distinguish the observation cutoff from the source retrieval date.
2. **Keep the candidate loop explicit.** For each cell, read the next candidate's annual pressure files, apply source quality exclusions, consolidate hours and expose the intermediate table. Reject candidates whose pressure-only coverage cannot possibly satisfy the agreed rule before requesting ERA5. This is an exact shortcut within preparation: final acceptance still requires matched, cleaned coverage. Download only attempted candidates, stopping a cell after its first acceptance.
3. **Retrieve primary inputs once per candidate.** Read available historical caches first, fetch missing ERA5 surface pressure, temperature and dewpoint over the required 2022–cutoff extent, and obtain orography at the station grid cell. Persist the extracted primary station series. Evaluate all daily windows, outlier fractions, offsets and historical steps locally; no network call belongs inside the daily window loop. Retrieve additional covariates and ERA5-Land for accepted stations afterwards; their availability does not decide primary acceptance.
4. **Save small cell checkpoints.** After each completed candidate, save the next candidate index, rejection counts and accepted station/window if present in one RDS file for that cell. Resume from that index and the existing input files. A crash before a checkpoint can repeat one candidate's local calculation, but cannot change the order or erase completed cells. Use one worker per cell and start with four workers, limiting simultaneous transfers.
5. **Commit files only after successful completion.** Write downloads, extracted Parquet files and cell checkpoints to a temporary file in the destination directory; read/check the expected schema and requested ERA5 date extent, then rename to the final path. Only the final path counts as complete. For station observations, naturally absent reporting dates are allowed; completeness of a download cannot be inferred from the station's last observation date. Reuse historical raw files; refresh attempted candidates' mutable 2026 annual files once for the frozen retrieval snapshot, then preserve that snapshot on restart. Derived caches must match the station coordinates, requested fields, time extent and saved run settings. Keep prior analyses readable until the replacement outputs pass their checks.
6. **Keep retrieval failures separate from rejection.** Use bounded retries for transient requests. If a required transfer still fails, leave that cell pending at the same candidate and continue independent cells. Retry that candidate on restart. Do not advance to another station or count a technical failure as a scientific rejection. A station-year absent from the frozen archive catalogue is genuine unavailability; a failed request for a listed file is not. Prevent final publication of a network while cells remain pending.

Use persistent station-series caches, not an unbounded on-disk mirror of ERA5 chunks. Inspection of `GeoPressureR::era5_arco_client()` shows that its object cache exists only inside the client call; it does not persist across candidates or restarts. Saving the extracted series is sufficient for a simple, restartable implementation. Neighboring candidates may reread a remote chunk, which is an acceptable speed trade-off for this one-off run. At the observed mean annual file size, five new annual files for 4,000–8,000 candidates would occupy roughly 11–22 GiB before reuse; primary station series and final outputs require additional space. Check disk use during the pilot and reserve room for final outputs. Do not eagerly download all 37,468 inventory stations or retain duplicate full chunk caches on this disk.

## Fit within the existing R workflow

Keep an ordinary top-to-bottom driver with sections for settings, inventory, candidate groups, cell processing and combination. Use short functions only for genuinely reused units: download/read a station file, prepare matched inputs, find a window and fit the step model. Keep the intermediate candidate, daily counts, selected window and station checks inspectable. Use the existing `data.table`/Arrow machinery for large inputs and `sf` for the grid; no new workflow framework or database is needed.

The change spans the existing pipeline; changing only station screening would leave conflicting calendar-year and weighting assumptions downstream:

- **Scripts 01–03:** replace the old candidate-frame dependency and calendar-year selection with direct inventory groups and the explicit cell/candidate loop. Move primary ERA5 retrieval into candidate preparation, with short reused retrieval functions.
- **Scripts 07–09:** carry `window_start` and `window_end`, preserve reusable core inputs, obtain retained-only covariates, and calculate errors for the exact accepted hours. Keep step-context observations distinguishable from the selected-year analysis observations. Do not reapply calendar-year outlier removal.
- **Scripts 11–12 and 18–20:** consume the acceptance decisions already made, replace selected-calendar-year joins with window membership, and apply equal GHCNh station weights throughout summaries and figures. Adapt existing temporal comparisons explicitly to rolling windows. Do not run a conflicting second step/offset selection downstream. Update explanatory methods and counts when the rebuild is complete.

## Checks before the full run

Use a small fixed pilot containing recent and older qualifying windows, coverage failures, outliers, offsets, insufficient step history and clear steps. Confirm the agreed dates, rounding, month-end/leap-day behavior, criterion boundaries and candidate replacement. Check the step model's rank and residual degrees of freedom as part of determining whether the required model can be fitted.

Interrupt and restart the pilot after a completed candidate and during a temporary-file write. Compare selected IDs, exact windows, accepted hours and rejection counts with an uninterrupted run. Inject one transfer failure and confirm it leaves the candidate pending. Run the same pilot sequentially and with four workers; selections must agree. Confirm each retained station contributes total weight one and the three formulas use identical accepted hours. These checks cover consequential logic and restart behavior; they do not require a general-purpose test framework.
